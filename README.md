# Тетрадь по информатике

Платформа для репетитора по информатике, готовящего учеников 8–9 классов к ОГЭ. Прототип в одном HTML-файле: вход по ролям, теория по каждому типу задания, банк заданий ФИПИ, сборка вариантов, проверка (авто и ручная), статистика и привязка родителей к ученикам.

Дизайн — «тетрадь в клетку» с красной линией полей, рукописными пометками учителя и кружками-оценками как в школьной тетради. Светлая и тёмная темы, адаптив под телефон.

---

## Возможности

### Три роли

| Роль | Что видит |
|---|---|
| **Учитель** | Полный CRUD: типы заданий, теория, банк ФИПИ, авторские задания, варианты, назначения, проверка работ, статистика класса, привязка родителей |
| **Ученик** | Теория по каждому типу (обязательна к прочтению перед решением), банк заданий, режим «решать по номеру», варианты, мой прогресс, работа над ошибками |
| **Родитель** | Только прогресс привязанных детей: недельная сводка, % по номерам и темам, что подтянуть |

### Модули

- **Справочник типов заданий ОГЭ (1–16)** — номер, название, тема, формат ответа (`number` / `text` / `sequence` / `file`), максимальный балл.
- **Теория перед каждым типом** — Markdown с кодом, таблицами, картинками; ссылка на видео; загрузка изображений через file input; отметка «прочитано» для ученика и статистика прочтения для учителя; возможность скрыть теорию, пока не готова.
- **Банк заданий** — задания ФИПИ и авторские в одном каталоге; фильтры по номеру, теме, источнику; режим «решать случайное №N»; импорт заданий из JSON.
- **Варианты** — ручная сборка (отметить задания) или авто («по одному заданию на каждый номер»); назначение ученикам с дедлайном и опциональным таймером; режим экзамена (разбор скрыт до завершения, таймер по умолчанию 150 минут).
- **Решение задания** — автопроверка коротких ответов (с нормализацией пробелов и регистра), ручная проверка файловых/развёрнутых ответов (задания №13–16: презентация, таблицы, Робот, программа). История попыток, мгновенный разбор после проверки.
- **Работа над ошибками** — автоматический список заданий, где ученик ошибся.
- **Статистика** — ученик видит % по номерам и темам + слабые места; учитель — матрицу «ученик × номер задания» с цветовой подсветкой; родитель — недельную сводку по ребёнку.
- **Настройки** — справочник типов, экспорт всех данных в JSON, импорт, сброс к демо, переключение темы.

## Технологии

- **HTML + CSS + ванильный JavaScript** — один файл, без сборки, без фреймворков.
- **localStorage** — все данные хранятся локально в браузере через слой `getX/saveX`, который позже заменяется на REST API без изменения вызовов.
- **[marked](https://cdn.jsdelivr.net/npm/marked)** — рендер Markdown для теории, условий и разбора.
- **[Lucide](https://unpkg.com/lucide)** — иконки.
- **Google Fonts** — Quicksand (основной), Caveat (рукописный), JetBrains Mono (код).
- **CSS Grid + Flexbox** — адаптивная вёрстка.
- **CSS custom properties** — палитра и тёмная тема через `data-theme="dark"`.

## Как запустить

### Вариант 1 — просто открыть

Скачайте `informatics-tutor.html` и откройте в любом современном браузере. Работает офлайн, ничего не устанавливается.

### Вариант 2 — через локальный сервер (рекомендуется)

Нужно для корректной работы `localStorage` в некоторых браузерах:

```bash
# Python 3
cd /path/to/project
python3 -m http.server 8000
# откройте http://localhost:8000/informatics-tutor.html

# или Node.js
npx serve .
```

## Модель данных

Слой `getX/saveX` поверх `localStorage` оперирует следующими сущностями:

```javascript
{
  users: [
    {id, role:'teacher'|'student'|'parent', name, initials, color,
     grade?,         // для student
     childIds?:[]    // для parent
    }
  ],
  taskTypes: [
    {num:1..16, title, topic, format, maxScore,
     theoryHidden, theory, theoryVideo, theoryImage}
  ],
  tasks: [
    {id, num, source:'fipi'|'author', topic, difficulty:1..3,
     fipiId, statement, image, answer, explanation}
  ],
  variants: [
    {id, name, taskIds:[], deadline, examMode, timerMin}
  ],
  assignments: [
    {id, variantId, studentId, deadline, startedAt, finishedAt}
  ],
  attempts: [
    {id, taskId, studentId, variantId?, answer, isCorrect, score,
     comment, ts, manual?}
  ],
  theoryRead: { '<studentId>_<taskTypeNum>': timestamp },
  settings: { theme }
}
```

### Экспорт / импорт

- **Экспорт** — все данные скачиваются одним JSON-файлом (`informatics-oge-YYYY-MM-DD.json`).
- **Импорт** — загружается ранее сохранённый JSON, текущие данные заменяются.
- **Импорт заданий** — массив заданий добавляется к существующему банку (без удаления).

## Что упрощено в прототипе

Эти ограничения принципиальны для прототипа на `localStorage` и должны быть решены в боевой версии:

1. **Нет аутентификации** — вход по выбору имени, у учителя формальный код `NB-2025`. Все данные в одном `localStorage` на устройстве.
2. **Файлы — data URL** — изображения теории и файлы ответов хранятся как base64 в `localStorage` с лимитом 200–500 КБ. Нет загрузки на сервер.
3. **Теория к заданиям №13–16** — заглушки.
4. **Таймер экзамена** — не блокирует отправку ответов по истечении (только визуальная индикация).
5. **Импорт заданий** — не проверяет дубликаты по `fipiId`.
6. **Нет серверной проверки кода** — задание №16 проверяется учителем вручную.
7. **Нет пагинации и полнотекстового поиска** — банк заданий умещается в памяти.
8. **Нет real-time** — ученик не видит моментально, когда учитель проверил работу (нужно перезагрузить страницу).

## Дорожная карта в production

Подробное обсуждение бэкенда — в отдельном документе. Кратко:

| Фаза | Что | Срок |
|---|---|---|
| 0. База | Docker Compose: Postgres + MinIO + API + фронт; Prisma-схема; миграция данных из JSON | 1 неделя |
| 1. Auth + users | JWT, RBAC, CRUD пользователей, привязка parent-child | 1 неделя |
| 2. Контент | task-types (теория), tasks (банк + авторские), variants, assignments | 1.5 недели |
| 3. Решение | attempts (автопроверка + ручная), статистика, работа над ошибками | 1.5 недели |
| 4. Файлы + проверка | загрузка в S3, signed URLs, ручная проверка с комментарием | 1 неделя |
| 5. Real-time | WebSocket, уведомления | 0.5 недели |
| 6. Песочница кода | Docker-runner для задания №16 (или [judge0](https://judge0.com/)) | 1 неделя |
| 7. Деплой + observability | production, бэкапы PSQL, логи, метрики | 0.5 недели |

**Рекомендуемый стек:** Node.js 20 + Fastify + TypeScript, PostgreSQL 16 + Prisma, MinIO/S3, WebSocket через `ws`, JWT в httpOnly cookie, Docker Compose для MVP → Kubernetes для прод.

Фронтенд почти не меняется: слой `getX/saveX` становится `async`, добавляется слой `auth` (токен, refresh), остальное (UI, компоненты, разбор Markdown) сохраняется.
